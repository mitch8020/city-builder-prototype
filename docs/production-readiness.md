# Local production-readiness inventory

Date: July 25, 2026

## Scope and safety boundary

This campaign covers the local Nashville Parcel Diorama and its packaged May 12,
2026 parcel snapshot. It does not access an authenticated account, production
deployment, private database, or real user record.

The only application role is an anonymous desktop explorer. There are no login,
authorization, editing, administrative, or destructive user workflows.

The current candidate also renders illustrative parcel massing from the
sanitized land-use code, improvement appraisal, and valid multistory floor
fields. It does not claim to contain surveyed building footprints or heights.

The packaged snapshot is production scale:

- 286,458 de-duplicated parcel records;
- 305,913 spatial-shard references;
- 570 FlatGeobuf shard files;
- approximately 130.8 MiB of FlatGeobuf data;
- owner names, mailing addresses, legal descriptions, and sale history omitted;
- civic parcel address, parcel identifiers, land use, zoning, acreage, and
  appraisal fields intentionally retained.

`npm run data:audit` decodes every shard, enforces the exact public field
allowlist, verifies geometry and record IDs, and reconciles bytes and counts
against the manifest. Rebuilding was intentionally not required because the
current snapshot already matches its source checksum and rebuilding would
replace the versioned output directory.

## Production-like local settings

- `npm run test:e2e` builds the production client and SSR bundles first.
- Playwright serves the built bundle with `vite preview` on
  `http://127.0.0.1:20073`.
- Chromium runs at the supported desktop size of 1440 by 900.
- Browser journeys run in one Chromium worker so the finite frame-budget gate
  is not contaminated by simultaneous WebGL renderers on the same workstation.
- Google basemap and Metro search responses are controlled independently per
  test; local parcel files remain the real production-scale package.
- Failure artifacts retain Playwright traces and screenshots.
- TanStack developer tooling remains a development dependency and is stripped
  from production builds by the first Vite plugin.

## Production-scale data acceptance inventory

| ID      | Data surface                        | Acceptance criteria                                                                                                                                                                                                | Finite risk-based edge cases                                                                                                                    |
| ------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| DATA-01 | Public parcel schema                | Every decoded record has exactly the 13 allowlisted civic fields: record and parcel IDs, feature/floor, address, acres, land-use code/label, zoning, and land/improvement/total appraisal.                         | Owner names, mailing addresses, legal descriptions, sale history, and any unexpected source field fail the audit.                               |
| DATA-02 | Production-scale volume             | The built package reconciles 286,458 unique records, 305,913 shard references, 570 FlatGeobuf shards, and 130.8 MiB against the versioned manifest.                                                                | Duplicate records across spatial shards de-duplicate by `rid`; missing, extra, or byte-mismatched shards fail.                                  |
| DATA-03 | Geometry and manifest integrity     | Every record has Polygon or MultiPolygon geometry, a nonnegative integer `rid`, an in-public-directory shard URL, and manifest counts matching decoded content.                                                    | Polygon holes, multipolygon parts, repaired rings, empty/invalid geometry, path traversal, and record-count drift.                              |
| DATA-04 | Optional-field and appraisal safety | Missing optional civic values remain renderable as “Not available”; nonnegative appraisal values populate stable quantiles without exposing a private field.                                                       | Missing address, land use, or zoning; zero appraisal; invalid/negative presentation values.                                                     |
| DATA-05 | Illustrative massing derivation     | Every land-use code present in the packaged manifest has an explicit safe classification; valid multistory floors can increase capped massing height; parcel selection remains bound to the exact parcel geometry. | Unknown future code, no improvement, park/vacant use, invalid floor text, condominium records, multipolygon, hole, narrow/degenerate footprint. |
| DATA-06 | Production-like local serving       | The production client/SSR build serves the versioned manifest, overview, and viewport shards through `vite preview`; workers load only the finite current/prefetch window and retain bounded idle cells.           | Slow/aborted shard, retry exhaustion, pan preemption, stale worker generation, cache eviction, and county-edge view.                            |

The source shapefile is intentionally absent from this sanitized checkout. The
already-built public package is validated in place with `npm run data:audit`;
`npm run data:build` is not run because it requires the private source input and
replaces the versioned output directory.
